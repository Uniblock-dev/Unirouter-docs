[Pi](https://pi.dev) is a terminal coding agent with a small tool surface and a JSON file for models. Adding this API is one provider entry. Unlike most harnesses here, Pi gives you a real output ceiling to set. Read [coding harnesses](/integrations/coding-harnesses) first.

## The configuration surface

The file is `~/.pi/agent/models.json`. Providers are keyed by a name you choose:

```json ~/.pi/agent/models.json
{
  "providers": {
    "hopscotch": {
      "baseUrl": "https://api.hopscotchlabs.ai/v1",
      "api": "openai-completions",
      "apiKey": "$HOPSCOTCH_API_KEY",
      "models": [
        {
          "id": "unirouter/auto",
          "name": "Default route via Hopscotch",
          "contextWindow": 200000,
          "maxTokens": 8192
        }
      ]
    }
  }
}
```

```bash
export HOPSCOTCH_API_KEY=ub_live_YOUR_KEY_HERE
```

**Pi does not append `/v1`.** Include it in `baseUrl`. The file is re-read each time you open `/model`, so you can edit it mid-session.

## `api` picks the wire, per provider

`api` takes `openai-completions`, `openai-responses`, `anthropic-messages` or `google-generative-ai`. It can be set on the provider or overridden on one model. `openai-completions` is chat completions. `openai-responses` is the other surface this API serves, which [Codex CLI](/integrations/codex-cli) documents. The other two leave the surface this site publishes, so nothing here says what comes back.

A provider speaks one protocol, so a wrong value does not produce a configuration error. It sends a differently shaped request to a real endpoint.

## The key, and the two forms that keep it out of the file

`apiKey` resolves three ways. Only one puts the secret in the file.

- `"$HOPSCOTCH_API_KEY"` reads an environment variable. A missing variable leaves the value unresolved, not empty.
- `"!command"` runs the value as a command and uses its output, the form for a password manager or keychain.
- Anything else is a literal. A plain uppercase word is the key itself, not a variable name.

`models.json` lives under your home directory, not your repository, but the environment form costs nothing. Pi resolves `!command` at request time with no caching or retry, so wrap a slow or rate-limited helper in your own script.

You can also store the credential with `/login` in `~/.pi/agent/auth.json`, or pass `--api-key`. A model with no auth configured still loads, but stays unselectable in `/model` and `--list-models`.

## List the models yourself

A provider entry has no discovery step. The models Pi offers are the ones you write down, and each `id` is a pinned id. Ask [`GET /v1/models`](/features/models) for the strings your key can call, and keep `unirouter/auto` in the file. Pi's extension API can also register a provider from an async factory that fetches a catalog at startup. That is more machinery than most people want.

## Set `maxTokens`, because here you can

`maxTokens` on a model is the output ceiling, and Pi applies its own default if you omit it. A realistic ceiling holds less against your spend rate cap and is charged the same, since the charge is for what was produced. Set `contextWindow` from the same catalog entry so Pi's context accounting is not guessing. [Rate limits and spend controls](/manage/spend-controls) covers the cap.

## `cost` is Pi's arithmetic, not ours

A model entry takes a `cost` block of per-million-token rates, with optional tiers. Pi uses it to show what a session cost. It has no effect on what you are charged, and nothing reconciles it against this platform. Leave it at zero and read [Activity](/manage/usage-and-metering). If you fill it in, treat Pi's figure as an estimate that drifts once a routing profile sends a turn elsewhere. [Models](/features/models) covers where prices come from.

## When a request shape needs correcting

Pi has a `compat` block, on the provider or a single model, for endpoints that are OpenAI-compatible in most respects. The first switches to check are `supportsDeveloperRole`, which decides whether the system prompt travels as `developer` or `system`, and `maxTokensField`, which picks `max_completion_tokens` or `max_tokens`.

We have not run Pi here, so we cannot tell you that you need either. If a reasoning model fails while an ordinary one works, `supportsDeveloperRole` is where to look.

## No embeddings feature found

Pi's documented tool surface reads, writes and edits files, and runs your shell. Its provider documentation names no embedding model and no meaning-based index of your repository. We did not audit its source to confirm the absence. If a feature fails against this API, check [embeddings](/integrations/coding-harnesses) first.

Subagents are an optional package. Each child it runs is its own conversation on the same key, with its own rows in Activity.
