[Gas Town](https://github.com/gastownhall/gastown) is a multi-agent workspace manager. It runs other people's coding agents in terminal sessions, gives each a role and a piece of work, and merges what comes back. [Gas City](https://github.com/gastownhall/gascity) is the same machinery as an SDK for building your own arrangement. Neither is a coding agent, so almost none of the configuration here is theirs. Read [coding harnesses](/integrations/coding-harnesses) first.

## No wire, no base URL, no key

Gas Town talks to no model and has no base URL or API key field. It orchestrates agents through terminal sessions and environment variables rather than linking against them. Its own words: integration is configuration rather than compilation.

So pointing Gas Town here means three steps. Pick a child agent this API serves, configure that child as its own page says, and use Gas Town's environment injection for the pieces that belong in the environment. Every question about the endpoint belongs to the child, including whether the base URL wants `/v1`. A town running two kinds of agent needs both answers.

## Registering an agent, and where the environment goes

For an agent Gas Town does not ship, write its preset yourself at `~/gt/settings/agents.json`. The field that matters is `env`, merged into the child's environment at launch:

```json ~/gt/settings/agents.json
{
  "version": 1,
  "agents": {
    "opencode-hopscotch": {
      "name": "opencode-hopscotch",
      "command": "opencode",
      "args": [],
      "env": {
        "HOPSCOTCH_API_KEY": "ub_live_XXXXXXXXXXXX"
      },
      "instructions_file": "AGENTS.md"
    }
  }
}
```

[OpenCode](/integrations/opencode) reads that variable through `{env:HOPSCOTCH_API_KEY}` in its own `opencode.json`, so the provider block stays in the child and only the secret is delivered here.

`~/gt` is outside your repository, which is a smaller exposure than the config files on [coding harnesses](/integrations/coding-harnesses). It is still a plain file holding a key. Reading the key from your own environment and leaving `env` out works wherever your child supports it. To change only the command:

```bash
gt config agent set opencode-hopscotch "opencode"
gt config default-agent opencode-hopscotch
```

## Gas City names the endpoint once

Gas City can do what Gas Town cannot: name the endpoint once for many agents.

Its `city.toml` has an `[upstreams]` table of named endpoint presets, selected per agent. An upstream carries a `base_url`, a credential as `api_key` or `auth_token`, and where needed the environment variable each harness expects. `base_url_env` and `api_key_env` let one upstream render into whatever names each child wants. Write a credential as a `$VAR` reference to keep the secret out of the file. `env` on the upstream is a raw escape hatch, merged last.

Set the base URL in the form the child wants, which for most children here means with `/v1` on the end. Use the `$VAR` form for the key.

## What this does to Activity

These tools run agents in parallel without a person in each turn, which is the traffic shape the [coding harnesses](/integrations/coding-harnesses) warnings are about, at larger scale.

Every turn of every child is a billed request on the same key. A town with several agents looping produces rows in [Activity](/manage/usage-and-metering) faster than anything else on these pages. The spend rate cap counts credit held, so concurrency is what reaches it. Where a child lets you set a maximum output, set it. [Rate limits and spend controls](/manage/spend-controls) covers the cap.

**Take `402` off any retry list you control.** A `402` with `insufficient_credit` is a balance, not a transient fault, and a supervisor that restarts a failed agent will rediscover that quickly.

## Beads is not in the way

Gas Town tracks work in Beads, a version-controlled issue database. It calls no model and needs no key, so it is not a second thing to configure. The merge queue and health patrol are shell and git. The model calls all happen inside the child.

## What we did not verify

- That a Gas Town or Gas City session against this API succeeds. Nothing was run.
- Whether an `env` entry reaches every child unchanged. We read the field and its examples, not each preset's launch.
- Whether `gt` or `gc` itself calls a model. Neither configuration surface carries a base URL or credential, but we did not audit either codebase.
- Anything about the `gemini`, `kiro`, `auggie`, `amp`, `copilot` or `omp` presets, including whether they accept a custom endpoint.
- How stable this is. Both projects are moving quickly, and Gas City calls its upstream layer a phase of work, not a settled surface.
