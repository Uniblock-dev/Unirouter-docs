[Cursor](https://cursor.com) is an editor with a chat pane and an agent. It takes an OpenAI API key and a base URL, so it can be pointed here. Read the next section before the configuration, because a custom base URL does not buy what most people expect. Then read [coding harnesses](/integrations/coding-harnesses).

## Your key and your requests still go through Cursor

Decide on this before anything below matters. Cursor's documentation says the key is sent to Cursor's backend with every request, because prompts are assembled there. The key is not stored and the transport is encrypted, but neither changes the shape. A custom base URL adds your endpoint to the path. It does not remove Cursor's.

Two consequences:

**Cursor's zero data retention policy does not apply when you bring your own key.** Cursor says so on the same page.

**Pointing Cursor at a private gateway does not make the traffic private to you.** If your prompts must not reach a third party, no setting documented here changes that. [Data and privacy](/manage/data-and-privacy) covers what happens once a request reaches us, which is a separate question.

Other harnesses on this site do not work this way, so a reader moving between pages could carry the wrong assumption here.

## The setting

In Cursor's settings, under Models, there is an OpenAI API key field and beside it **Override OpenAI Base URL**. Paste the key into one and the base URL into the other, then save and let Cursor verify them.

```text Base URL
https://api.hopscotchlabs.ai/v1
```

```text API key
ub_live_XXXXXXXXXXXX
```

**Include `/v1`.** Cursor appends `/chat/completions`. This is the opposite of Claude Code's convention and the same as Codex's.

Cursor's documentation does not describe this field. Its name and behaviour come from Cursor staff replies on its forum, the latest dated 2026-08-21. If the field has moved, search for the mechanism rather than the menu path.

## The override is global, including for Cursor's own models

A Cursor staff reply dated 2026-08-21 says that while the override is enabled, every request to an OpenAI-family model goes to your endpoint, including models chosen from Cursor's built-in list.

A built-in model name is not one this API accepts. It arrives unpinned and is refused with `400` and `model_id_not_pinned`. The refusal is correct, but it looks like the model is broken. There is no per-model override. To use a Cursor model, turn the setting off.

## Pin the model id

Cursor takes model ids as free text under the same Models settings. Use an id this API accepts: a provider-pinned `provider/model`, or `unirouter/auto`, which means whichever route your workspace made its default. [Models](/features/models) has every accepted form, and [Routing profiles](/features/routing-profiles) covers the fixed id.

A model added this way is a chat model. It is not available to the features below.

## What keeps using Cursor's own models

Cursor's documentation says a custom key works with chat models and that Tab completion keeps using Cursor's built-in models. Your autocomplete is not billed here.

A forum reply from Cursor staff adds that subagents do not inherit the custom base URL or model list. They fall back to Cursor's own models silently, rather than refusing. Those requests never appear in [Activity](/manage/usage-and-metering).

On a Cursor team plan, an administrator can turn bring-your-own-key off for everyone under Team Settings. In that case none of this applies.

## What we did not verify

- That a Cursor session against this API succeeds. Nothing was run.
- Whether Apply uses the custom key. Cursor's documentation says custom keys work with chat models and does not name Apply either way.
- Whether Cursor still builds an embeddings-backed index of your repository. Its current documentation describes a grep-based search tool and does not mention embeddings or indexing. We assert neither answer. If a search feature fails against this API, check [embeddings](/integrations/coding-harnesses) first.
- Whether the override reaches Cursor's cloud or background agents. An open request asks for it, which suggests it does not, and Cursor has not said so.
- Prompt caching through Cursor. Prompts are assembled on Cursor's servers, so what reaches a provider is not what your editor sent, and we have not measured the effect on a cache prefix.
